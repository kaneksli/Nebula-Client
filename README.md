# Nebula VPN — каркас проекта

Рабочий скелет кроссплатформенного VPN/прокси-клиента на Tauri + React + sing-box,
по ТЗ: боковая панель подписок, панель подключения с 3D-глобусом, абстракция
`CoreManager` под движки прокси.

## Что уже работает

- **UI полностью собран и живой** (`npm run dev` открывает рабочий интерфейс
  в браузере на моках, без Rust/Tauri):
  - боковая панель — аккордеон подписок, список серверов с пингом и
    цветовой индикацией, кнопка Auto, контекстное меню удаления, "+"
  - панель подключения — 3D-точечный глобус (Three.js + three-globe),
    облёт камеры к серверу при подключении, акцентный маркер, бейдж
    "Подключено: …", таймер сессии, переключатель TUN/Proxy, статистика
    скорости
  - модалка настроек со всеми разделами из ТЗ (внешний вид, подключение,
    диагностика)
- **Rust-бэкенд**: трейт `CoreManager` (src-tauri/src/core_manager.rs) —
  любой движок (sing-box сейчас, Xray-core потом) реализует один и тот же
  интерфейс `connect/disconnect/stats/measure_ping`. `SingBoxCore`
  (`singbox.rs`) собирает конфиг sing-box, запускает его как дочерний
  процесс, читает статистику через Clash API. Команды Tauri
  (`main.rs`) и системный трей (`tray.rs`) подключены.

## Важная оговорка

В песочнице, где собирался этот каркас, нет Rust-тулчейна и GUI-окружения
(`cargo` не установлен, WebKit/нативные зависимости Tauri недоступны) —
весь Rust-код написан и вычитан вручную, но **ни разу не скомпилирован и
не запущен**. Прежде чем полагаться на сборку, прогоните `cargo check` в
`src-tauri/` на своей машине и поправьте то, что реальный компилятор
найдёт (несовпадения версий крейтов, опечатки в типах и т.п.) — для
проекта такого размера это нормально и быстро правится.

## Что реализовано по-настоящему (не заглушки)

- **Парсинг подписок** (`subscription.rs`) — реальные парсеры
  `vless://`, `vmess://`, `trojan://`, `hysteria2://`/`hy2://`, `ss://`
  (включая устаревшую полностью-base64 форму), сборка их в sing-box
  outbound-блоки (reality/utls/ws/grpc/xhttp-транспорты и т.д.).
  `add_subscription` реально скачивает URL, декодирует тело (обычный
  список строк или base64), парсит каждую ссылку и сохраняет результат.
- **Определение страны/флага** (`geo.rs`) — по флагу-эмодзи или
  двухбуквенному коду страны в remark'е ссылки, с таблицей центроидов
  ~50 стран для позиционирования маркера на глобусе. Это эвристика, а
  не честный geoip по IP — при желании можно заменить на реальный запрос
  к geoip-сервису.
- **Хранение на диске** (`store.rs`) — подписки и настройки сохраняются
  в `subscriptions.json` / `settings.json` в конфиг-директории
  приложения и загружаются при старте.
- **Реальный пинг** — `ping_all` конкурентно (не по очереди) измеряет
  TCP-connect время до каждого сервера через `CoreManager::measure_ping`
  и возвращает обновлённый список; фронтенд применяет именно эти цифры,
  а не случайный джиттер (джиттер остался только как запасной вариант
  для `npm run dev` без Rust-бэкенда).
- **Статистика в реальном времени** — пока активно соединение, фронтенд
  раз в 1.2с вызывает `get_stats`, которая читает Clash API sing-box;
  случайные числа остались только как fallback вне Tauri.
- **Повышение прав для TUN** (`elevate.rs`) — TUN-режим запускает
  sing-box через `pkexec`/`sudo` (Linux), `osascript … with administrator
  privileges` (macOS) или `Start-Process -Verb RunAs` (Windows); Proxy-режим
  никогда не повышает права, так как не в этом нет необходимости.
  **Это нельзя проверить из песочницы** — для pkexec нужен polkit-агент
  и графическая сессия, для остальных двух — реальные macOS/Windows.
  Проверьте каждый путь на своей ОС перед релизом.
- **Иконки** — реальные PNG для бандла и трея (сгенерированы, не
  заглушки по смыслу, но по виду — просто кружок; замените на
  финальный дизайн). `.ico`/`.icns` не сгенерированы (нужны
  специализированные инструменты), поэтому таргеты `msi`/`dmg` временно
  убраны из `tauri.conf.json` — добавьте обратно, когда появятся
  настоящие `.ico`/`.icns`.
- **Настройки** — `get_settings`/`save_settings` реально читают и пишут
  JSON на диск; UI-переключатели в `Settings.jsx` пока не вызывают эти
  команды (это следующий шаг — сам факт хранения уже работает).

## Что всё ещё нельзя считать готовым

1. **Сам бинарник sing-box.** Приложение ожидает его в
   `<app-config-dir>/bin/sing-box(.exe)` — скачивание/обновление этого
   бинарника при установке нигде не реализовано, это задача инсталлятора.
2. **WinTun-драйвер на Windows** для TUN-режима — должен ставиться
   инсталлятором отдельно, в коде приложения этого шага нет.
3. **UI-переключатели настроек** (автозапуск, автоподключение, тема и
   т.д. в `Settings.jsx`) ещё не вызывают `get_settings`/`save_settings` —
   команды готовы, провода от чекбоксов к ним ещё нет.
4. **Xray-core как второй движок.** Трейт `CoreManager` готов, но
   реализован только `SingBoxCore`.
5. **Сборка и подпись инсталляторов** (`.msi`, `.dmg`, нотаризация на
   macOS, подпись на Windows) — вне кода приложения, делается отдельно
   на каждой целевой машине/CI.

## Запуск

```bash
npm install
npm run dev          # UI в браузере на моках, без Rust
# или, когда Rust-тулчейн и Tauri CLI настроены:
npm run tauri dev    # полноценное окно с бэкендом
```

Структура:

```
src/                   React-фронтенд
  components/
    Sidebar.jsx         подписки + серверы
    Globe.jsx            3D-глобус (three-globe)
    ConnectionPanel.jsx  кнопка подключения, статы, режим
    Settings.jsx         настройки
src-tauri/
  src/
    core_manager.rs      трейт абстракции движка
    singbox.rs            реализация под sing-box
    tray.rs                системный трей
    main.rs                 команды Tauri, состояние приложения
```
